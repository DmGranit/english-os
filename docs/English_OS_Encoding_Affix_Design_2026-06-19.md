## 0. Рамка: encoding ≠ maintenance

Два режима научения, сейчас перекошены в сторону второго:

| Режим | Что это | Состояние сейчас |
|---|---|---|
| **Encoding** | интенсивное ПЕРВОЕ научение слова (предъявление → активное использование → перенос) | 🔴 тонкий: NEW = MCQ «что значит X?» (узнавание), продукция отложена в box3 |
| **Maintenance** | поддержка выученного спейсингом («вспомнил/забыл», интервалы Лейтнера) | 🟢 развит |

Решение: достроить encoding-такт. «Вспомнил/забыл» **не выкидываем** — это законный maintenance зрелых слов. Меняем только МОМЕНТ ПЕРВОГО НАУЧЕНИЯ.

🔬 Основания: desirable difficulty (Часть 1 канона), выталкивание к продукции (Swain), морфологическая осознанность ускоряет рост словаря и декодирование (Nation, Bauer & Nation — «семья слов» уже включает производные → числовая опора «3000 семей»).

## 1. Морфология: честная граница (что работает, что нет)

🟧/🔬 Английский — две морфологии, ведут себя противоположно:

| | Латино-греческий слой | Германский бытовой слой |
|---|---|---|
| примеры | cred, tract, spect, port | get, make, house, hand |
| множится через | **корень + аффикс** (credible, incredible, discredit) | **фразовые + сложение** (get up/over, household) |
| аффиксные правила | работают (декодирование ✅) | почти не работают |

**Следствия для дизайна:**
- Аффиксный слой даёт эффект на латино-деловом слое; на германском ядре ценность несут фразовые/сложение (уже частично есть: GR1, phrasal).
- Множитель — это **декодирование/узнавание** (догадаться о незнакомом), 🔬 для чтения/роста словаря. НЕ автоматическая продукция и НЕ генерация слов по правилам (спеллинг, выбор аффикса, дрейф смысла → брак). Поэтому **слова материализуем как карточки**, а не генерим из правил.
- Аффиксы **не заучиваются списком** — насмотренность (повторная экспозиция в контексте).

## 2. Данные (хранение — вариант i: материализация + слой-учитель)

### 2.1. `affix_ref` (новая таблица)
🎯 Справочник аффиксов как обучающие «леса».
🔧 `affix TEXT PK · type TEXT(prefix|suffix) · meaning_ru TEXT · function TEXT (смена части речи / роль) · examples TEXT (2–3 прозрачных) · note TEXT`.
Объём: ~60–80 высокочастотных аффиксов (un-, re-, in-/im-, dis-, pre-, mis-, over-, under-, -er/-or, -tion/-sion, -ity, -ness, -ment, -ize/-ise, -ify, -ful, -less, -able/-ible, -al, -ous, -ic …).
🧪 Сид идемпотентен; `grep affix_ref` по `.py` ≠ 0 (читается, не мёртвый груз — урок C3/G0).

### 2.2. `content.derivation` (новое поле)
🎯 Связка производного слова с разбором.
🔧 JSON/строка: `base` (исходное слово/корень) + `affix` (какой аффикс) + опц. `note`. Напр. для familiar: `{base:"family", affix:"-ar", gloss:"имеющий свойство"}`.
🧪 Заполняется при обогащении (см. §4); пусто для непроизводных — норма.

### 2.3. Что переиспользуем
`root_ref` (есть), `word_family`/поле family (есть), `deep_view` рендер (есть), движок SRS/QA-стерео (есть). Новое — только `affix_ref` + `derivation` + точки показа/упражнения.

## 3. Encoding-урок: три такта

### Такт 1 — Богатое предъявление  (📍 отдельный encoding-рендер, НЕ `_card_payload` — реш. D2)
🎯 Слово как живой узел, а не «слово=перевод».
🔧 При первом показе слова: перевод + гнездо производных + **разбор словообразования** (база + аффикс, аффикс выделен: `modern·ize`) + 1–2 примера фраз/предложений. Источник — `content` + `derivation` + `affix_ref` + блоки `deep_view`, БЕЗ генерации на лету. **Гнездо за первый контакт — заглавное слово + ≤3 самых полезных/прозрачных производных** (когнитивная нагрузка ~3–4; реш. D4); остальное гнездо — по «🔍 Глубже». Насмотренность копится продольно, не крамом.
📍 Отдельный путь (свой рендер), переиспользует блоки `deep_view`; SRS-`_card_payload` не трогаем.
🧪 NEW-карточка показывает заглавное+≤3 производных+разбор+пример; аффикс визуально акцентирован.

### Такт 2 — Закрепление сразу (микс по слову, вариант C)  (📍 новый обработчик после предъявления)
🎯 Активное использование сразу, объективный зачёт — НЕ «вспомнил/забыл».
🔧 Форма зависит от типа слова (критерий — данными, реш. D3):
- **гнездовое/латинское** (корень в `root_ref` с лат./греч. origin ИЛИ есть `derivation`/семья с аффиксами) → **сборка**: «собери прилагательное от `family`» → familiar; или вставь верную форму в предложение.
- **простое/германское/фразовое** (иначе) → **продукция** RU→EN: напечатать показанное слово/чанк (Swain).
- неоднозначно → продукция (всегда валидна, мягкая деградация).
Грейдер объективный (как typed/`_one_edit_away`, узкий LLM-чек при необходимости). Вне SRS первого знакомства (не двигает Лейтнера преждевременно — как P1).
🧪 После предъявления приходит упражнение нужной формы по типу слова; верный ответ зачтён объективно; промах → подсказка + журнал.

### Такт 3 — Перенос в сценарий  (📍 `_call`/`scn_words` грунтовка сценария)
🎯 Закрепление в реальном контексте.
🔧 Сценарная сессия приоритетно вплетает слова, ВВЕДЁННЫЕ СЕГОДНЯ (из encoding-урока), в целевые слова сценария.
🧪 Слова сегодняшнего урока появляются в сценарной грунтовке; видны в разборе ИТОГа.

## 4. Источник производных и аффиксного разбора (стык с конвейером наполнения)

🎯 Чтобы гнёзда были полны, а разбор честен.
🔧 Дополнить `enrich.py` (встроенный конвейер):
- **передавать целевой смысл** из сбора в `enrich_word` (чинит дрейф «patient→терпеливый», найденный в пилоте 19.06);
- генерировать `derivation` (база+аффикс) для производных, аффикс сверять с `affix_ref`;
- `validate`: `root=="null"`→None; `dna_idea`/`thinking_frame` сверять со списком (не форсить бизнес-фрейм на A1); QA-стерео += проверка «family[] — настоящие однокоренные, аффикс назван верно».
🧪 Карточка производного несёт корректный `derivation`; QA ловит ложную морфологию и сенс-дрейф.

> Контент-кандидаты собираются агентным конвейером (пилот 19.06: фан-аут сборщиков → дедуп → судьи) и проходят `enrich.py`. Это отдельный, уже работающий слой; здесь — что он должен дозаполнять (derivation).

## 5. Аффиксная насмотренность (сквозной принцип)
🎯 Аффикс оседает через объём экспозиции, не зубрёжку.
🔧 Разбор `база+аффикс` с мягким акцентом показывается ВЕЗДЕ, где всплывает производное: encoding-предъявление (т.1), блок «🌱 семья», раскрытие ответа в review, «🔍 Глубже». Аффикс НИКОГДА не тестируется как изолированный юнит.
🧪 Один и тот же аффикс виден на многих словах в обычном потоке; отдельного «теста аффиксов» нет.

## 7. Риски и честные оговорки (A-метки)
- 🔬 морфологическая осознанность → декодирование/рост словаря (читать); 🟧 что это даёт прирост АКТИВНОЙ продукции — не доказано, меряем.
- Германское ядро аффиксами не покрывается — там фразовые/сложение (не натягивать аффиксный разбор на get/make).
- Генерацию слов по правилам НЕ делаем (брак на нерегулярности) — только материализованные выверенные карточки.
- Не ломать maintenance: «вспомнил/забыл» и спейсинг остаются для зрелых слов.

## 8. Решённые вопросы (экспертно — лингвист-педагог, 2026-06-19)

1. **Список аффиксов.** Опора: **Bauer & Nation 1993** (уровни продуктивности) + частотность приставок (Sowell/White: топ-20 приставок ≈97% слов с приставками). Курируем **~60–70 ДЕРИВАЦИОННЫХ** аффиксов (смысловые приставки + суффиксы смены смысла/части речи). **Флексии исключаем** (-s/-ed/-ing/сравнит. -er/-est — это грамматика, не множитель). Тир по продуктивности (продуктивные — в насмотренность первыми). Выверка — QA-стерео.
2. **Рендер encoding — ОТДЕЛЬНЫЙ путь**, не `_card_payload` (он перегружен P2). Принцип единственной ответственности; переиспользует блоки `deep_view`.
3. **Критерий гнездовое/простое — данными:** есть корень в `root_ref` (лат./греч. origin) ИЛИ `derivation`/аффиксальная семья → сборка; иначе (германское/голое/фразовое) → продукция; неоднозначно → продукция.
4. **Гнездо за первый контакт — ≤3 производных** (нагрузка ~3–4); полное гнездо по «🔍 Глубже»; насмотренность продольная.

> На этапе плана уточняются только реализационные детали (точные строки сида аффиксов, имена функций), не дизайн-развилки.
