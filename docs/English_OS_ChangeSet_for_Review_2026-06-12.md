### B0 / B6 — маршрутизация свободного текста (`bot.py: _process_user_text`)

**Симптом (вживую, оба разбора + БД):**

- B7 — «Fill … 5» без слеша → FLOW вместо конвейера (то же семейство).

**Предлагаемое направление:**
- Текст-ответ уходит в активный контекст (карточка / ожидание `/add` / `/fill`) **раньше**, чем в стоп-интент и catch-all FLOW/feedback.
- Для `/add` ввести состояние «жду слово» (флаг в `user_data`), по образцу уже существующих `await_feedback` / `act_wid` / `warm_wid`.

**ЧЕМ МОЖНО УРОНИТЬ — главное для коллеги:**
В `_process_user_text` уже ~семь ранних `return` в строгом порядке: slot-input → end-trigger → MAIN_BUTTONS → await_feedback → act_wid → warm_wid → typed_wid → активная колода. Вставка новой ветки или сдвиг стоп-детектора может сломать:
- (а) завершение сессии словом «Итог»/«стоп» (`_is_end_trigger`);
- (б) ответ в активной колоде (`review_queue` + свежесть < 600с);
- (в) `await_feedback` (тот же механизм, что предлагается для `/add` — проверить, что не конфликтуют).

→ **Коллеге:** проверить, что новый порядок веток не перехватывает эти три живых пути. Это самый рискованный пункт changeset'а.

### B2 — `_swap_in` фолбэки (`bot.py: ~141–164`)

**Симптом:** при сбое HTML-edit (1) фолбэки (2)/(3) шлют **сырой текст** → битый `**` на старте сценария (лог `swap_in edit failed` 07:52:22).

**Направление:** в шагах (2)/(3) применять `_to_html(...)` + `parse_mode="HTML"`, не сырой текст.

**ЧЕМ УРОНИТЬ:** если HTML-сущности в сиде кривые — повторный HTML-edit может падать так же. Нужен порядок «чистый HTML → экранированный плоский», не «сырой». → **Коллеге:** проверить, что фолбэк не зациклится и не потеряет сообщение совсем (последний шаг должен гарантированно доставить хоть что-то).

### B8 — детерминизм `/read` (`db.py: target_words`)

**Симптом:** `ORDER BY priority DESC, word_id ASC LIMIT 4` — без `RANDOM`/ротации → три чтения подряд про одни слова (pay/feel/sorry/friend).

**Направление:** рандомизация / ротация / исключение недавно показанных в `target_words`.

**ЧЕМ УРОНИТЬ:** `target_words` используется не только `/read`, но и как «новые ~2%». → **Коллеге:** проверить **всех потребителей** `target_words` — рандомизация не должна сломать логику, где ожидается стабильный топ-приоритет.
